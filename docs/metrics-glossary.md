# 电商指标与字段说明

这些是业务指标和数据字段，不是 Quick 的配置参数。先理解它们代表什么，再检查助手是否用对数据。金额示例均来自本仓库模拟数据，币种为 USD（美元）。

## 常见缩写

| 术语 | 全称与中文 | 日常怎么理解 |
| --- | --- | --- |
| SKU | Stock Keeping Unit，库存管理单元 | 用来区分商品款式、规格的编码；本例每行汇总一个 SKU 的七天经营数据 |
| POD | Print on Demand，按需印制/定制生产 | 收到订单并满足确认稿等条件后生产，生产时间和运输时间分开考虑 |
| ROAS | Return on Ad Spend，广告支出回报率 | 每花 1 元广告费，按指定归因规则记到广告名下多少元销售额 |
| ACOS | Advertising Cost of Sales，广告销售成本比 | 每 1 元广告归因销售额，对应多少广告花费，通常用百分比表示 |
| CPA | Cost per Acquisition / Action，获客或行动成本 | 含义取决于平台如何定义转化；本案例明确指“每个广告归因订单的广告成本”，不是每个新客户成本 |
| CLV / LTV | Customer Lifetime Value / Lifetime Value，客户终身价值 | 一个客户在整个关系期预计带来的价值，需要说明是收入还是贡献/利润口径 |
| EOQ | Economic Order Quantity，经济订货批量 | 一种权衡订货与持有成本的库存模型；本例生产位不是成品库存，不用该模型直接计算产能 |

## ROAS：广告带来的销售额与广告费之比

**ROAS = 广告归因销售额 ÷ 广告花费。**

本例 T 恤广告归因销售额为 1000 美元，广告花费为 300 美元，所以 ROAS = 1000 ÷ 300 ≈ **3.33 倍**。意思是按本例归因规则，每花 1 美元广告费，对应约 3.33 美元归因销售额。

这不代表赚了 3.33 美元利润，也不证明这些销售全部是广告带来的增量。还需要扣除商品、配送、平台等成本。T 恤全渠道销售额为 2400 美元，不能用 2400 ÷ 300 替代本例 ROAS。

杯子的 ROAS = 1600 ÷ 400 = **4 倍**，比 T 恤高，但扣除列示成本后的贡献为 −100 美元，且质量未放行。因此不能只看 ROAS 决定加预算。

## CLV：一个客户长期能带来多少价值

CLV 关注同一个客户未来可能持续购买多少次、每次带来多少价值，以及关系能持续多久。

例如，假设一个客户每年购买 2 次，每次净收入 50 元，关系持续 3 年，不考虑折现和变化，则简化的**收入型生命周期估计**为 2 × 50 × 3 = 300 元。这是解释概念的假设例子，不是本案例的计算结果，也不是通用预测公式。

若采用贡献或利润口径，还需要定义并扣除相应成本；更完整的模型可能考虑留存、客户服务成本、获客成本和未来价值折现。使用时必须先约定口径。

**本仓库的 SKU 汇总表不能支持客户级 CLV 预测。** 至少需要能连接多次购买的客户标识、订单日期、金额、退款与成本，以及适当长度的观察期和留存假设。订单数不等于客户数。

“沉睡客户”也要先定义：例如某类业务约定超过特定天数未购买，再根据客户最后购买时间判断。不能从三行 SKU 数据编造沉睡客户名单。

## 其他可以计算的指标

| 指标 | 本案例公式 | T 恤示例 | 要注意什么 |
| --- | --- | --- | --- |
| 净销售额 | 销售额 − 退款 | 2400 − 120 = 2280 美元 | 是本例简化口径，真实业务还可能有折扣、税费等定义 |
| 贡献额 | 销售额 − 退款 − 生产 − 配送 − 平台费 − 广告费 | 2400 − 120 − 800 − 400 − 240 − 300 = 540 美元 | 没有扣除未列示的固定费用或税费，不称为净利润 |
| 贡献率 | 贡献额 ÷ 净销售额 | 540 ÷ 2280 ≈ 23.68% | 本例分母是净销售额；分母非正时不能正常解释 |
| ACOS | 广告花费 ÷ 广告归因销售额 | 300 ÷ 1000 = 30% | 相同口径且分母非零时，与 ROAS 互为倒数 |
| CPA | 广告花费 ÷ 广告归因订单数 | 300 ÷ 30 = 10 美元/归因订单 | 不能当作新客成本，也不保证下一单仍花 10 美元 |
| 退款金额率 | 退款金额 ÷ 总销售额 | 120 ÷ 2400 = 5% | 是金额比例，不是退款订单比例 |

## 什么是广告归因

广告归因是按一定规则，把销售或订单记到某次广告互动名下。归因窗口决定回看多长时间；归因模型决定如何分配功劳。

本例采用一致的教学归因窗口，未指定某个平台的真实归因模型。真实报表比较前，需要核对窗口、渠道、币种和模型；不同口径不能直接拼起来。

`partial` 表示归因数据尚不完整。空白不等于零，也不能用总销售额减去已知部分来补造广告归因。

## CSV 字段速查

| 字段 | 含义 |
| --- | --- |
| `sku` | 商品编码 |
| `period_start` / `period_end` | 经营数据的统计起止日期 |
| `orders` | 该 SKU 窗口内的订单数，不是客户数，也不是明细行数 |
| `gross_sales_usd` | 退款前的全渠道销售额，美元 |
| `refund_amount_usd` | 同窗口列示退款金额，美元 |
| `production_cost_usd` | 生产成本，美元 |
| `shipping_cost_usd` | 配送成本，美元 |
| `platform_fee_usd` | 平台费用，美元 |
| `ad_spend_usd` | 广告花费，美元 |
| `attributed_ad_sales_usd` | 按归因规则记录的广告销售额，美元 |
| `attributed_orders` | 广告归因订单数 |
| `attribution_status` | `complete` 为本例归因完整，`partial` 为尚未齐全 |
| `currency` | 币种；本例 USD |
| `as_of` | 履约状态快照的业务时点 |
| `capacity_48h_units` | 活动未来 48 小时剩余可用生产位，不是成品库存；订单数和件数还需另行核对 |
| `capacity_status` | 产能是否已确认；`confirmed` / `unconfirmed` |
| `proof_template_status` | 确认稿模板状态；`approved` 为已批准，`pending` 为待处理 |
| `design_license_status` | 设计授权状态；`approved` 为已批准，`unconfirmed` 为未确认 |
| `quality_status` | 质量状态；`clear` 为本例无质量阻断，`hold_pending_review` 为暂缓、等待复核 |
| `owner` | 对应记录的负责人；其他事项可能有不同责任人 |
| `is_synthetic` | 是否为模拟数据，本例为 True |

商品目录中的 `material` 是材质，`personalization` 是定制选项，`production_business_days` 是生产工作日范围，`us_shipping_business_days` / `uk_shipping_business_days` 是美国/英国运输工作日范围，`care` 是护理说明，`claim_rule` 是宣称限制。生产与运输时间不能混为一谈，也不自动构成到货保证。

具体计算口径以 [metric_contract.md](../examples/pod-operations/data/metric_contract.md) 为准；实际答案用 [核对清单](review-checklist.md) 检查。
